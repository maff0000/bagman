# Runtime dependencies for BAGMAN CD-2.
#
# jsonschema and rfc3339-validator were introduced by WI-2, both
# explicitly authorised by the PL for that work item:
#
#   jsonschema          - validates every domain object's to_dict()
#                          output against its contracts/*.schema.json
#                          file (Draft 2020-12) before it is accepted.
#                          Also used by WI-3's
#                          scripts/generate_architecture_memory.py to
#                          validate component.yaml manifests against
#                          contracts/manifest/bagman.component_manifest.v1.schema.json.
#   rfc3339-validator    - jsonschema's built-in "date-time" format
#                          checker only registers itself if this
#                          package is importable (see
#                          jsonschema._format); without it, `format:
#                          date-time` is silently unenforced. This is
#                          exactly the gap WI-1 flagged.
#
# Versions pinned to the current stable release of each as of this
# work item (2026-09-12) — see the WI-2 delivery report for the
# environment check that produced these:
#   jsonschema 4.10.3 was already installed in the delivery
#   environment (a transitive dependency from elsewhere), but the
#   latest stable release, 4.26.0, is pinned here deliberately since
#   there was no prior CD-2 code depending on the older version's
#   behaviour.
#
# PyYAML - moved here by WI-3. It was previously dev-only
# (requirements-dev.txt) because nothing outside the test suite used
# it. WI-3's scripts/generate_architecture_memory.py now imports it
# directly to parse component.yaml manifests and
# config/base/entities.yaml, and that script is meant to be run
# outside test contexts (by a developer or a CI drift-check job, not
# only by pytest) — so it is now an application-adjacent tool
# dependency, not merely test tooling, and belongs in this file
# instead. Pinned to the version already used by requirements-dev.txt.
#
# referencing - pinned explicitly by the PL after CD-2 audit flagged it:
# core/contract_validation.py imports `referencing` directly
# (Registry/Resource/DRAFT202012) to cross-resolve $ref between
# contracts/*.schema.json files. It was previously only present as an
# undeclared transitive dependency of jsonschema>=4.18 — correct today,
# but a package a module imports directly should be pinned directly,
# not left to arrive incidentally via another package's own dependency
# choices, which could change in a future jsonschema release. Pinned to
# the version that was already resolving and passing all 102 tests.
#
# boto3 - introduced by CD-3 WI-2, PL decision already made (not the
# dedicated `minio` package): boto3 is the official, extremely
# well-established AWS SDK for Python, and talks to any S3-compatible
# endpoint (including MinIO) by pointing `endpoint_url` at it —
# chosen for portability toward a future real cloud object store, per
# PID §16's own stated goal ("this allows later migration to another
# S3-compatible service or cloud object store without rewriting
# evidence semantics"). Used by persistence/objects/minio_store.py
# only; core/ and services/evidence/ never import it directly (PID
# §53), and tests/integration/test_architecture_boundaries.py does not
# scan persistence/ so this does not affect that boundary check.
#
# Pinned to 1.43.93, the latest stable release as of this work item
# (2026-09-12; confirmed via `pip index versions boto3`). The
# environment already had 1.34.46 installed as a transitive
# dependency of nothing in particular; since no prior CD-2/CD-3 code
# depended on that older version's behaviour, the latest stable
# release is pinned here deliberately, matching the same rationale
# WI-2 (CD-2) used for jsonschema above.
#
# persistence/objects/minio_store.py also imports
# `botocore.exceptions` directly (to catch BotoCoreError/ClientError
# and re-raise as the canonical StorageError rather than letting a
# raw botocore exception escape) — but botocore's version is left to
# boto3's own dependency resolution rather than pinned separately
# here, since botocore is boto3's tightly-coupled low-level
# transport and the two are always installed as a matched pair; there
# is no independent version choice to make the way there was for
# `referencing` (a jsonschema dependency imported for an unrelated
# reason, cross-$ref resolution, that could in principle diverge from
# jsonschema's own pin).
#
# Do not add anything else here without flagging it to the PL first.
jsonschema==4.26.0
rfc3339-validator==0.1.4
PyYAML==6.0.2
referencing==0.37.0
boto3==1.43.93
